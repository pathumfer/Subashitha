# සුභාෂිත v4 Development Plan

Updated folder structure and implementation roadmap based on technical design v4.

## Major Changes from v3 → v4

### Architecture Shifts
- **SEO First:** Razor pages render `/si/{slug}`, `/en/{slug}`, `/browse/*` for Google indexing
- **Signed Publishing:** Manifests with Ed25519 signatures, integrity checks, and safe activation
- **Offline + Indexing:** Service worker, IndexedDB for favorites, stale-while-revalidate caching
- **Content Security:** Per-page CSP with hashed scripts, Trusted Types, character validation
- **Smart UX:** One search box, device keyboard + optional Sinhala picker, offline-capable

### Removed / Deprecated
- ~~`current.txt`~~ → replaced by manifest-based activation
- ~~Public accounts~~ → corrections without login, status via private token
- ~~Separate staging host~~ → local + Access-protected production staging

### Added
- Stable entry IDs (ULID) in content JSON
- Manifest signing (Ed25519 key)
- Service worker + offline cache
- Sitemaps + `robots.txt` (generated by ETL)
- CSP manifest (hashes for inline scripts)
- English headword pages
- GitHub Actions content-publish workflow
- Per-field character allow-lists for submissions

## Key Implementation Details

### Folder Organization Rationale

| Folder | Why |
|--------|-----|
| **web/src/app** | Each route is a Page or layout, App Router convention |
| **web/src/components/keyboard** | Docked UI is decoupled from search logic |
| **web/src/components/admin** | Review UI with grapheme awareness separate from submission |
| **web/src/workers** | Service worker + Web Worker trie loader kept explicit |
| **api/Pages/ContentPages** | Razor pages for SEO, separate from API |
| **api/Features/Admin** | Publishing + manifest activation logic isolated |
| **api/Data/Models** | Stable IDs, slugs, redirects as core data layer |
| **etl/src** | Each step of the pipeline is a module (validate, sign, build, manifest) |

### File Naming Conventions

- **Next.js:** `ComponentName.tsx`, `useHookName.ts`, `lib/module-name.ts`
- **.NET:** `FeatureName/EndpointName.cs`, `Services/ServiceName.cs`
- **Python ETL:** `module_name.py`, `test_module_name.py`
- **Secrets:** never committed; stored as GitHub Actions secrets

### Critical v4 Patterns

1. **Stable IDs:** Entry `id` never changes; slugs can redirect via `id`
2. **Signed Manifests:** Every publish is cryptographically verified before activation
3. **Per-Field Validation:** Sinhala fields reject Latin, Latin fields reject Sinhala control chars
4. **Grouped Search Results:** Sinhala first if it scores higher, else English first; both shown in one list
5. **Offline-Capable:** Service worker + IndexedDB means favorites work on the bus
6. **CSP without nonces:** Hashed inline scripts, Trusted Types for XSS hardening
7. **Razor + Next.js Split:** Content pages for SEO, app pages for interactivity; no duplication
